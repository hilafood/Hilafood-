# هیلافود — مرحله چهارم: رابط حساب و کنترل دسترسی دوره‌ها

## آنچه اضافه شده
- `account.html` و `account.js`: رابط فارسی واکنش‌گرا برای شماره موبایل، درخواست/تأیید OTP، شمارش معکوس ارسال مجدد، نمایش وضعیت نشست و خروج.
- رابط از مسیرهای موجود `/api/auth/request-otp`, `/api/auth/verify-otp`, `/api/auth/me` و `/api/auth/logout` استفاده می‌کند. توکن نشست در JavaScript یا localStorage ذخیره نمی‌شود؛ اعتبار نشست فقط با کوکی HttpOnly و بررسی سرور مشخص می‌شود.
- لینک حساب کاربری به منوی سایت اضافه شده است.
- `course.html` و `course.js` صفحه نمایش اطلاعات دوره و فصل/درس‌ها را اضافه می‌کنند.
- `GET /api/course-content?course_id=<id>` فقط دوره فعال و ساختار فصل/درس را از D1 می‌خواند. متن و رسانه درس پولی برای مهمان یا حساب فاقد مالکیت معتبر بازگردانده نمی‌شود.
- بررسی مالکیت معتبر سمت سرور برای `course_entitlements`, `course_orders` و `users` آماده شده است؛ معیار طراحی شامل سفارش `paid`، مرجع تأییدشده `verified_at` و شماره تأییدشده است. با این حال، کلید فعال‌سازی خرید در کد عمداً `false` است؛ بنابراین در این مرحله حتی رکورد مالکیت آزمایشی هم محتوای پولی را باز نمی‌کند.
- آدرس مستقیم رسانه برای درس پولی از API بازگردانده نمی‌شود، حتی اگر مالکیت وجود داشته باشد؛ تحویل امن رسانه پولی هنوز پیاده‌سازی نشده است.

## مهاجرت و داده‌ها
هیچ مهاجرتی روی D1 واقعی اجرا نشده و هیچ فایل مهاجرت جدیدی در این مرحله اضافه نشده است. API برای تشخیص خطای ساختار/جدول، با پاسخ 503 بسته می‌شود و محتوای پولی را افشا نمی‌کند.

مسیرهای فعلی به جداول افزوده‌شده در مهاجرت‌های قبلی نیاز دارند:
1. `migrations/0002_course_purchase_foundation.sql`: ستون تخفیف دوره، کاربران، OTP، نشست‌ها، سفارش دوره و مالکیت دوره.
2. `migrations/0003_auth_rate_limits.sql`: محدودیت نرخ و triggerهای امنیتی.

پیش از هر اجرای واقعی باید از D1 نسخه پشتیبان قابل‌بازیابی تهیه شود، شناسه و محیط دیتابیس کنترل شود، هر دو مهاجرت ابتدا روی کپی آزمایشی اجرا شوند و آزمون بازیابی انجام شود. اجرای واقعی نیازمند دستور و تأیید جداگانه است.

## محدودیت مهم رسانه مستقیم
این مرحله از طریق API محتوای پولی را به مهمان/غیرمالک نمی‌دهد و URL درس پولی را هم در پاسخ API نمی‌فرستد. با این حال، اگر قبلاً URL یک ویدئوی پولی روی سرویس عمومی یا نشانی مستقیم قابل دسترس ذخیره شده باشد، خود این برنامه نمی‌تواند دسترسی مستقیم به آن سرویس خارجی را مسدود کند. برای حفاظت واقعی رسانه باید فایل‌ها در ذخیره‌سازی خصوصی قرار بگیرند یا یک درگاه تحویل رسانه با کنترل مالکیت و URL امضاشده/کوتاه‌عمر طراحی و آزمایش شود. تا آن زمان ویدئوی پولی در این رابط نمایش داده نمی‌شود. این مورد هنوز تأیید امنیتی کامل دریافت نکرده است.

## پرداخت و سفارش‌ها
- پرداخت واقعی و خرید دوره فعال نشده است.
- هیچ کاربری خریدار تلقی نمی‌شود و دسترسی درس پولی عمداً غیرفعال است.
- مسیرهای محصولات و سفارش‌های موجود تغییر منطقی نکرده‌اند؛ `app.js` فقط پیوند کارت دوره را به صفحه دوره اضافه می‌کند.
- هیچ D1، Secret یا تنظیم Cloudflare تغییر نکرده است.

## آزمون‌ها
Workflow شاخه کاری آزمون‌های موجود احراز هویت/مهاجرت را به آزمون‌های جدید `tests/course-access.test.mjs`, `tests/course-access-api.test.mjs` و `tests/auth-flow-stage4.test.mjs` گسترش می‌دهد. آزمون‌ها از داده‌های ساختگی استفاده می‌کنند و پیامک یا پرداخت واقعی ارسال نمی‌کنند. اجرای مرورگر واقعی و آزمون end-to-end روی Cloudflare در این مرحله انجام نشده است؛ نتیجه آن نباید با آزمون‌های واحد/API یا بررسی ایستا یکی گرفته شود.
